# Basket & Discount Engine

Учебный Android-проект: расчёт итогового чека корзины со скидкой по промокоду и стоимостью доставки. Главная цель — показать разработку через тесты (TDD, цикл Red-Green-Refactor).

## Что считает приложение

По корзине и промокоду собирается чек:

1. **Subtotal** — сумма позиций (цена × количество).
2. **Скидка** — процент от Subtotal, если промокод действует. Просроченный или неизвестный код скидку не даёт.
3. **DiscountedTotal** — Subtotal минус скидка (не ниже нуля).
4. **Доставка** — считается от DiscountedTotal: если он достигает порога (50.00) — бесплатно, иначе 5.00.
5. **Total** — DiscountedTotal плюс доставка.

Порядок важен: скидка считается от Subtotal, а доставка — уже от суммы после скидки.

## Деньги и округление

Все суммы — `BigDecimal`. Промежуточные расчёты идут с полной точностью, округление (`HALF_UP`, 2 знака) применяется один раз — при сборке чека, в `Money.round` внутри `CalculateBasketUseCase`. 
Это единственная точка округления в проекте.

## Структура модулей

- **`:domain`** — чистый Kotlin, вся бизнес-логика (расчёт, скидки, доставка, модели). Не зависит от Android.
- **`:data`** — источники данных: локальный список промокодов, демо-корзина, системная дата. Реализует интерфейсы из `:domain`.
- **`:app`** — Android-модуль. Собирает зависимости через Hilt. Содержательного экрана нет — фокус на логике.

Зависимости направлены внутрь: `:app` → `:data` → `:domain`.

## Стек

- Kotlin, Coroutines
- Hilt — внедрение зависимостей
- JUnit 5 + MockK — тесты

Retrofit и kotlinx.serialization подключены как задел под внешний источник данных, но сейчас не используются.

## Коммиты и TDD

Префиксы коммитов отражают фазы цикла:

- `test:` — сначала пишется падающий тест (Red);
- `feat:` — затем минимальная реализация, тест зеленеет (Green);
- `refactor:` — по необходимости, без изменения поведения.

## Запуск тестов

```
gradlew :domain:test
gradlew :data:testDebugUnitTest
```
